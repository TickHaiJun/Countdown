### 一、ESC 退出大屏 —— bug 已定位（性质比想象中严重）

`src/app/fullscreen/page.tsx` 第 87–100 行的键盘 effect：

```ts
/* 键盘：← → 切换，Esc 退出，F 切换全屏 */   // ← 注释里的承诺
useEffect(() => {
  const onKey = (event: KeyboardEvent) => {
    if (event.key === 'ArrowLeft') { ...; go(-1); }
    else if (event.key === 'ArrowRight') { ...; go(1); }
  };                                        // ← 只有左右箭头
  ...
}, [go]);
```

**ESC 和 F 一个都没实现**，注释是空头支票。

更要紧的是 i18n 里 `fullscreen.clickHint = '按 Esc 可随时退出'`（`zh.ts:334`）
—— **界面上明文承诺了，代码里没有**。这属于「文档/UI 与实现不一致」的真 bug，不只是「少个快捷键」。

对照：番茄钟的大屏浮层 ESC 是**实现了的**（`PomodoroTimer.tsx:227` → `closeImmersive()`）。

修 ESC 时要处理的两个细节：
1. **浏览器原生全屏会吞掉第一次 ESC**（浏览器用它退出全屏，keydown 不一定传到页面）。
   所以「原生全屏中按 ESC」→ 退出全屏；「非原生全屏按 ESC」→ 离开页面，语义要定清楚。
2. `/fullscreen/` 上的 `全屏` 与 `退出大屏` 是**两个不同按钮**：`exitFullscreen()` 只退原生全屏、
   不离开页面；旁边另有一个回首页的图标链接。所以 ESC 到底等价于哪一个，需要海军拍板。

海军给的是 4 套（1 个默认 + 3 个命名主题）：

| # | 名称 | 类型 | 底色 | 层数 |
| --- | --- | --- | --- | --- |
| 默认 | `GrainGradient`（`@paper-design/shaders-react`） | **WebGL** | 未指定 | 未指定 |
| 1 | Golden Hour | CSS aura | `#faf8f2` **浅色** | 2（multiply） |

**关键验证（决定整个方案是否成立）**：检查了 `out/_next/static/chunks/*.css`，
Tailwind v4 输出的是

```css
.text-ink-2{color:var(--color-ink-2)}
.border-line{border-color:var(--color-line)}
.bg-elev{background-color:var(--color-elev)}
```

而 token 声明在 `@layer theme{:root,:host{...}}` 里。**结论：工具类引用的是 `var()`**，
所以只要在**更靠后的、无 layer 的**规则里写 `:root[data-theme='x'] { --color-base: ... }`
（无 layer 规则在级联上胜过 `@layer theme`，且 `:root[data-theme]` 特异性 0,2,0 > `:root` 的 0,1,0），
**全站 token 化的样式会自动跟随，组件一行都不用改**。运行时换主题在架构上完全成立。

**成本极不对称**：
- Blueprint / Aurora Borealis：与现有 Diamond Storm **完全同构**（body 底色 + 透明容器 + CSS 层），
  换一套 layer 的 `background` + `mix-blend-mode` + blur 即可，**几乎白送**。
- **Golden Hour 是唯一真正的成本**，因为它是**浅色**。

**`GrainGradient` 真实 API**（读自 `dist/shaders/grain-gradient.d.ts`）：
```ts
interface GrainGradientParams {
  colorBack?: string;
  colors?: string[];        // 上限 7 个（grainGradientMeta.maxColorCount = 7）
  softness?: number;        // 0–1
  intensity?: number;       // 0–1
  noise?: number;           // 0–1
  shape?: 'wave'|'dots'|'truchet'|'corners'|'ripple'|'blob'|'sphere';
}
// + ShaderMotionParams { speed?, frame? }  → speed={0} + frame={n} 可冻结成静态帧
// + ShaderComponentProps { minPixelRatio?, maxPixelCount?, width?, height?, ...div props }
// 官方现成预设：defaultPreset / wavePreset / dotsPreset / truchetPreset / ripplePreset / blobPreset
```
`speed={0} + frame` 这条很关键 —— 正好能接现有的 `settings.reduceMotion`。

### 十、字号档位的技术阻塞（重要发现）

**103 处字号写死 `text-[Npx]`，只有 1 处用 rem。** 分布最密：
`PomodoroBoard` 9 / `HolidayCard` 9 / `EventFormDialog` 9 / `CountdownsBoard` 9 /
`HolidayHero` 8 / `EventCard` 7 …

后果：**直接在 `html` 上改 `font-size` 不会生效** ——
px 字号不动，而 Tailwind 的间距类（`px-4`/`py-9`/`mt-3`）全是 rem，会一起放大
→ 间距变大、文字不变、**布局直接坏掉**。

三条出路：

| 方案 | 做法 | 代价 | 风险 |
| --- | --- | --- | --- |
| **A（推荐）** | 103 处 `text-[13px]` → `text-[calc(13px*var(--fs-scale))]`，只缩放字号 | 机械替换，可脚本化 | 纯字号放大，卡片内可能溢出 |
| B | `html{font-size:X%}` + 103 处改 rem | 字号与间距**等比**放大 | 与 Hero 的 `calc(100svh - 68px)` 首屏预算冲突（红线 #8） |
| C | `html{zoom:X}` | 零重构 | 同样与 viewport 单位打架，且 `position:fixed` / 全屏需复验 |

倾向 **A**：语义最贴「字体大小」、不动间距、不碰首屏高度预算。若海军其实想要「整体缩放」，则选 C。

### 本轮修掉的两个**真 bug**（都不是新写的代码，属既有隐患被这轮验证挖出）

**1. 首屏防闪脚本静默失效（严重）**
产物里是 `localStorage.getItem(undefined)`。根因：`lib/appearance.ts` 从 `@/store/countdown-store`
读 `STORAGE_KEY`，而那个模块带 `'use client'` —— 服务端组件链路（`layout.tsx`）间接引过去，
Next 把这次导入换成**客户端引用代理**，取值恒为 `undefined`，**且不报任何错**。
`JSON.stringify(undefined)` 返回的不是字符串而是 `undefined`，模板字面量就把字面量
`undefined` 烙进产物 → 脚本首行 `return`，整套防闪逻辑死掉。
现象：浅色主题（golden）刷新时先闪一帧深色再翻白。

修法：
- 新增中性模块 `src/lib/storage-keys.ts` 存键名；`countdown-store.ts` 改为再导出。
- `appearance.ts` 加**构建期断言** `assertInlined()`，值为 undefined 直接让构建失败。
- 单测那条 `expect(str).toContain(STORAGE_KEY)` 是**自证式断言**：`toContain(undefined)`
  会把入参转成字符串 `"undefined"` 而照样通过。改成钉字面量 `'"countdown:v1"'` +
  `not.toContain('getItem(undefined)')`。

**2. 本地构建漏 basePath → 整站 404**
`next.config.ts` 的 basePath 读 `NEXT_PUBLIC_BASE_PATH`。裸跑 `npm run build` 产出
`basePath=''`，铺到项目页 `/Countdown/` 下资源全 404：页面零样式、React 不 hydrate、
点按钮全无反应，**但控制台不报错**（资源 404 不走 CDP 的 Runtime 域，只走 Network 域）。
新增 `npm run build:pages`（`scripts/build-pages.mjs`，把前缀钉死，等价 CI）。

### 验证手法（本轮新增，都是反直觉的）

- **CDP 只听 Runtime 域会漏掉资源 404**：必须 `Network.enable` + 收
  `Network.loadingFailed` / `responseReceived(status>=400)`。第一版过滤规则里
  `/404 \(/` 恰好把最关键的信号吃掉，才让「7/60 全挂」查了两轮。
- **`Page.addScriptToEvaluateOnNewDocument` 记录「主题历史值序列」**才是「无闪烁」的真凭据。
  只看「刷新后仍是 golden」证明不了任何事——hydration 迟早会把它改对。
  实测：`[__no-root__ | null | golden]`，且 golden 落在 `readyState === 'loading'`（解析期，早于首绘）。
- 写这个探针时踩了 **`setInterval(0)` 在无头页面被节流到秒级**：观察器直到 `load` 完才挂上，
  把解析期的写入整个错过，假报「没写入」。改成观察 `document`（`subtree` 天然覆盖根元素，
  不需要等 `<html>` 出现、也不用定时器）才准。
- **`fs.rm` 在 Windows 会走安全删除垫片并超时**，脚本启动阶段直接炸。清 localStorage
  改用 CDP `Storage.clearDataForOrigin`，别碰文件系统。
- 生产构建会改写字面量，断言前必须规范化：`#fff` / `#ffffff`、`rgba(28,20,8,0.045)` → 8 位 hex
  `#1c14080b`（**alpha 只有 256 级，0.045→0.043 有精度损失**，别比字符串，判语义）、
  `.35` / `opacity(.45)`（去掉小数点前导 0）。
- 语言必须钉死：`detectLocale()` 读 `navigator.language`，无头 Chrome 默认 en-US，
  而文案定位器全是中文。`--lang=zh-CN` + CDP `Emulation.setUserAgentOverride.acceptLanguage`
  （**注意 `Emulation.setLocaleOverride` 不改 `navigator.language`，无效**）。

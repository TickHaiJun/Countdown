## 第三轮：海军说「点了没反应 / 首页太垃圾」→ 定位到根因

### 结论：**不是代码问题，是 Next 16 dev 的跨域资源拦截**

海军从 `http://192.168.0.39:3000/` 访问 dev server，Next 16 **默认阻断非白名单 host 访问
`/_next/hmr`**，导致客户端 bootstrap 卡住、**hydration 从未发生**。所有交互失效。

dev server 自己的日志（`.next/dev/logs/next-development.log`）写得非常明确：

```
⚠ Blocked cross-origin request to Next.js dev resource /_next/hmr from "192.168.0.39".
Cross-origin access to Next.js dev resources is blocked by default for safety.
To allow this host in development, add it to "allowedDevOrigins" in next.config.js and restart:
  allowedDevOrigins: ['192.168.0.39']
```

（`127.0.0.1` 同样被拦，日志里也有一条。）

**修法**：`next.config.ts` 加 `allowedDevOrigins: ['192.168.0.39','127.0.0.1','localhost']` → 重启 dev。
顺带清一次 `.next`（Turbopack 日志报过 "filesystem cache has been deleted because we previously
detected an internal error"，是我上次删 `.next` 留下的）。

### 证据链（怎么确认的）

| 检查 | 结果 | 含义 |
| --- | --- | --- |
| 页面上 DOM 节点有无 `__reactFiber$` / `__reactProps$` | **全为 `[]`** | React 从未在客户端渲染，纯 SSR 静态 HTML |
| console / exception 事件 | **零异常** | 不是代码抛错，是被"温柔地"拦住 |
| HMR WebSocket | 反复 `failed` | 与日志里的 Blocked 对应 |
| `h1` 文本 | `···` | `HolidayHero` 的 `ready = now > 0` 永远为 false |
| 点「设置」「隐私模式」 | `domDelta: 0` | 无事件处理器 |
| 点导航链接 | 页面确实跳转 | 原生 `<a>` 跳转，不依赖 JS —— 所以只有"像链接的"能点 |

## 第六轮：非安全上下文 bug 修复 + 番茄钟页面（v3）

### 1. 报错根因：非安全上下文（`http://<LAN-IP>`）下 API 直接 undefined

`Uncaught TypeError: crypto.randomUUID is not a function at handleSubmit (EventFormDialog.tsx:251)`。

**根因**：`crypto.randomUUID` / `navigator.clipboard` / `navigator.serviceWorker` **只在 secure context
（https / localhost）存在**。海军从 `http://192.168.0.39:3000` 访问 → 全是 `undefined`。
**但 `crypto.getRandomValues` 在非安全上下文里仍然可用**（这一点很关键，是兜底方案的立足点）。

新增三个共用工具，**红线 #14：禁止直接调 secure-context-only API**：

### 3. 新增 `/pomodoro/` 番茄钟页

- 逻辑层 `src/lib/pomodoro.ts` **纯函数**（可测）：`nextPhase`（第 4 个专注 → 长休；手动跳过 `counted=false` 不推进周期）、
  `cyclePosition`、`displaySeconds`（ceil）、`clockParts`、`clampConfigNumber`、`phaseDurationMs`、`localDayKey`
- `src/store/pomodoro-store.ts`：**存 `endsAt` 时间戳，不存递减计数** —— 剩余时间永远算 `endsAt - now`，
  避免后台标签页被节流导致漂移。`advance(counted, autoStart?)`，`shouldRun = autoStart ?? config.autoNext`
- `PomodoroClock.tsx` **复用 `FlipClock` 导出的 `FlipTile`**（`function FlipTile` → `export function FlipTile`），
  分:秒 两段，`data-phase` 驱动配色：focus `#60a5fa` / short `#34d399` / long `#2dd4bf`
- `PomodoroTimer.tsx`：**两条结算路径**（本轮最关键的语义修正）
  - 冷启动 hydrate 时发现 `running && endsAt <= now`（页面关着时已走完）→ `advance(true, false)` **停机等用户**，不自动开跑
  - 页面开着时到点 → `advance(true)` 按 `config.autoNext` 自动进入下一阶段
  - 用 `settled` ref 保证 hydrate 结算只跑一次（否则会和第二条 effect 打架）
- 大屏浮层走 `ui-store.immersiveOpen`（带 body 滚动锁 + 键盘 Space/R/F/Esc）；`ShortcutProvider` 的
  `overlayOpen` 已纳入 `immersiveOpen`，大屏打开时全局快捷键让位
- 浏览器全屏用原生 Fullscreen API；`StoreHydration` 里补 `usePomodoroStore.persist.rehydrate()`
- 今日统计 `hooks/use-today-stats.ts`：显示层比 `localDayKey(now)` 与 `statsDay`，跨天自动归零（无 mount 副作用）
- `TopBar` 加导航项（`Timer` 图标，`match: p => p.startsWith('/pomodoro')`）；页面挂全套全局浮层避免 `n`/`e` 快捷键死锁
